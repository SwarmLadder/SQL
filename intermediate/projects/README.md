# Intermediate projects

Each project is a set of tickets with acceptance criteria, like real work. Write your own SQL file first, run it with `python tools/run_sql.py <file>`, then compare with the reference solution.

| # | Project | Scenario | Reference |
|---|---|---|---|
| 01 | [Sales Dashboard with CTEs and Windows](01_sales_dashboard.md) | Leadership wants a monthly dashboard: revenue, order count, change versus last month, year-to-date, and a ranked list of the most valuable customers. | [SQL](01_sales_dashboard.sql) |
| 02 | [Customer Activity and Retention](02_customer_activity.md) | Growth wants to understand the customer lifecycle: when people first order, whether they come back, and how sign-up month relates to their first payment. | [SQL](02_customer_activity.sql) |
| 03 | [Cohort and Retention Report](03_cohort_retention.md) | The marketing team runs campaigns per sign-up month and needs a cohort report: how many customers each month brought in, how many converted, how quickly, and who came back. | [SQL](03_cohort_retention.sql) |

Every project uses the same 100-point review rubric (in each brief). Aim for 80+.
