# Basics projects

Each project is a set of tickets with acceptance criteria, like real work. Write your own SQL file first, run it with `python tools/run_sql.py <file>`, then compare with the reference solution.

| # | Project | Scenario | Reference |
|---|---|---|---|
| 01 | [Store Sales Report](01_store_sales_report.md) | The shop owner wants a first sales report: what each paid order was worth, which products sell, and which products nobody has bought. | [SQL](01_store_sales_report.sql) |
| 02 | [Safe Catalog Management](02_catalog_management.md) | Merchandising needs to add, re-price and retire products without ever damaging the live catalog. Every change must be previewed, checked and reversible. | [SQL](02_catalog_management.sql) |
| 03 | [Customer Health Check](03_customer_health_check.md) | Customer success wants to know who is active, who needs a follow-up, and whether the data itself can be trusted before a campaign goes out. | [SQL](03_customer_health_check.sql) |

Every project uses the same 100-point review rubric (in each brief). Aim for 80+.
